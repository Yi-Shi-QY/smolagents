### What is a tool, and how to build one?
The `Tool` class is the base for creating custom functionalities that your AI agent can use. You can define a tool by subclassing `Tool` or by using the `@tool` decorator on a function.

Here's how to define a tool by subclassing:
```python
from smolagents import Tool

class HFModelDownloadsTool(Tool):
    name = "model_download_counter"
    description = """
    This is a tool that returns the most downloaded model of a given task on the Hugging Face Hub.
    It returns the name of the checkpoint."""
    inputs = {
        "task": {
            "type": "string",
            "description": "the task category (such as text-classification, depth-estimation, etc)",
        }
    }
    output_type = "string"

    def forward(self, task: str):
        # Note: This specific tool's implementation uses huggingface_hub.list_models,
        # which requires network access. When designing tools for purely offline use,
        # ensure their forward method does not make network calls.
        from huggingface_hub import list_models # Network-dependent import

        model = next(iter(list_models(filter=task, sort="downloads", direction=-1)))
        return model.id

model_downloads_tool = HFModelDownloadsTool()
```

The custom tool subclasses [`Tool`] to inherit useful methods. The child class also defines:
- An attribute `name`, which corresponds to the name of the tool itself. The name usually describes what the tool does.
- An attribute `description` is used to populate the agent's system prompt.
- An `inputs` attribute, a dictionary defining the expected inputs with their types and descriptions.
- An `output_type` attribute, which specifies the output type (e.g., "string", "image", "number").
- A `forward` method which contains the core logic to be executed.

Alternatively, for simpler tools, you can use the `@tool` decorator:
```python
from smolagents import tool

@tool
def simple_adder(a: int, b: int) -> int:
    """
    Adds two integers. This tool is purely local and requires no network access.

    Args:
        a: The first integer.
        b: The second integer.
    """
    return a + b

# simple_adder_tool will be an instance of a Tool subclass
# simple_adder_tool = simple_adder 
# print(simple_adder_tool.name) -> "simple_adder"
# print(simple_adder_tool.description) -> "Adds two integers..."
```
The function's docstring is used for the description, and type hints are used for `inputs` and `output_type`. The `@tool` decorator automatically handles the creation of the `Tool` subclass instance.

And that's all it needs to be used in an agent!

### Saving and Loading Tools Locally

You can save your tool's definition to a local directory using the [`~Tool.save`] method. This method serializes your tool's code and metadata, making it easy to store, share, or reuse in other projects. The `save` method will typically create a Python file (e.g., `tool.py` or a name you specify based on `tool_file_name` argument) containing your tool's class definition and a `requirements.txt` if your tool has specific dependencies (detected from its imports). It can also generate an `app.py` for a Gradio interface if `make_gradio_app=True` (which is the default).

```python
# Assuming model_downloads_tool is an instance of a class inheriting from Tool
output_directory = "./my_custom_tools/model_downloader"
# This will save model_download_counter.py (or the name you provide in tool_file_name) 
# and potentially app.py/requirements.txt in ./my_custom_tools/model_downloader
# The .save() method itself is a local filesystem operation.
model_downloads_tool.save(output_directory, tool_file_name=model_downloads_tool.name) 
```
When saving, ensure your tool's code, especially the `forward` method and any helper methods, is self-contained or relies on standard libraries / specified requirements. Imports should generally be within the methods or at the top of the tool's Python file for clarity when saved.

To load a tool from its saved Python code file, you can use the [`~Tool.from_code`] class method. This method takes the Python code as a string. You'll typically read this from the `.py` file where the tool was saved.

```python
from smolagents import Tool, CodeAgent # Assuming CodeAgent and a model are defined

# Path to the saved tool's Python file
# This should match the tool_file_name used during save, or the default 'tool.py'
tool_code_path = "./my_custom_tools/model_downloader/model_download_counter.py" 

with open(tool_code_path, "r") as f:
    tool_code_content = f.read()

# Load the tool using from_code
model_download_tool_loaded = Tool.from_code(tool_code_content)

# Alternatively, you can load a tool from its dictionary representation
# This dictionary can be obtained from tool_instance.to_dict()
# tool_dict_example = model_downloads_tool.to_dict()
# model_download_tool_from_dict = Tool.from_dict(tool_dict_example)
```

Make sure the Python file (e.g., `model_download_counter.py`) primarily contains the tool class definition that inherits from `Tool` and any necessary imports for that tool to function. The `from_code` method executes this code in a new module and looks for a class that is a subclass of `Tool`.

Once loaded, the tool instance (e.g., `model_download_tool_loaded`) can be used in your agent:
```python
# model = ... (initialize your model, e.g., InferenceClientModel())
# agent = CodeAgent(tools=[model_download_tool_loaded], model=model)
# agent.run("Use the model download counter for text-classification.")
```

This local saving and loading mechanism allows for modular tool management.

A tool is mostly a function that an LLM can use in an agentic system.

But to use it, the LLM will need to be given an API: name, tool description, input types and descriptions, output type.

So it cannot be only a function. It should be a class.

So at core, the tool is a class that wraps a function with metadata that helps the LLM understand how to use it.

Here's how it looks:

```python
from smolagents import Tool

class HFModelDownloadsTool(Tool):
    name = "model_download_counter"
    description = """
    This is a tool that returns the most downloaded model of a given task on the Hugging Face Hub.
    It returns the name of the checkpoint."""
    inputs = {
        "task": {
            "type": "string",
            "description": "the task category (such as text-classification, depth-estimation, etc)",
        }
    }
    output_type = "string"

    def forward(self, task: str):
        # Note: This specific tool's implementation uses huggingface_hub.list_models,
        # which requires network access. When designing tools for purely offline use,
        # ensure their forward method does not make network calls.
        from huggingface_hub import list_models

        model = next(iter(list_models(filter=task, sort="downloads", direction=-1)))
        return model.id

model_downloads_tool = HFModelDownloadsTool()
```

The custom tool subclasses [`Tool`] to inherit useful methods. The child class also defines:
- An attribute `name`, which corresponds to the name of the tool itself. The name usually describes what the tool does. Since the code returns the model with the most downloads for a task, let's name it `model_download_counter`.
- An attribute `description` is used to populate the agent's system prompt.
- An `inputs` attribute, which is a dictionary with keys `"type"` and `"description"`. It contains information that helps the Python interpreter make educated choices about the input.
- An `output_type` attribute, which specifies the output type. The types for both `inputs` and `output_type` should be [Pydantic formats](https://docs.pydantic.dev/latest/concepts/json_schema/#generating-json-schema), they can be either of these: [`~AUTHORIZED_TYPES`].
- A `forward` method which contains the inference code to be executed.

And that's all it needs to be used in an agent!

There's another way to build a tool. In the [guided_tour](../guided_tour), we implemented a tool using the `@tool` decorator. The [`tool`] decorator is the recommended way to define simple tools, but sometimes you need more than this: using several methods in a class for more clarity, or using additional class attributes.

In this case, you can build your tool by subclassing [`Tool`] as described above.

### Saving and Loading Tools Locally

You can save your tool's definition to a local directory using the [`~Tool.save`] method. This is useful for sharing tools or for organizing your projects. The `save` method will create a Python file (e.g., `tool.py`) containing your tool's code and a `requirements.txt` if needed.

```python
# Assuming model_downloads_tool is an instance of a class inheriting from Tool
output_directory = "./my_custom_tools/model_downloader"
# This will save model_download_counter.py (or similar, based on tool.name) 
# and potentially app.py/requirements.txt in ./my_custom_tools/model_downloader
# The .save() method itself is a local filesystem operation.
model_downloads_tool.save(output_directory, tool_file_name=model_downloads_tool.name) 
```

To load a tool from its saved code, you can use the [`~Tool.from_code`] class method. This method takes the Python code as a string. You'll typically read this from the `.py` file where the tool was saved.

```python
from smolagents import Tool, CodeAgent

# Read the tool code from the saved file
tool_code_path = "./my_custom_tools/model_downloader/model_download_counter.py" # Adjust filename if needed
with open(tool_code_path, "r") as f:
    tool_code_content = f.read()

# Load the tool using from_code
model_download_tool_loaded = Tool.from_code(tool_code_content)

# You can also load a tool from its dictionary representation
tool_dict = model_downloads_tool.to_dict()
model_download_tool_from_dict = Tool.from_dict(tool_dict)
```

Make sure the file `model_download_counter.py` only contains the tool class definition and necessary imports. The `from_code` method expects to find a single class that inherits from `Tool` within the provided code string.

You can then use `model_download_tool_loaded` or `model_download_tool_from_dict` in your agent:
```python
# model = ... (initialize your model, e.g., InferenceClientModel())
# agent = CodeAgent(tools=[model_download_tool_loaded], model=model)
# agent.run("Use the model download counter for text-classification.")
```

This local saving and loading mechanism allows for modular tool management.

### Import a Gradio Space as a tool (Network Dependent)

You can directly import a Gradio Space from the Hub as a tool using the [`~Tool.from_space`] method! This method inherently requires network access to communicate with the Gradio Space.

You only need to provide the id of the Space on the Hub, its name, and a description that will help your agent understand what the tool does. Under the hood, this will use [`gradio-client`](https://pypi.org/project/gradio-client/) library to call the Space.

For instance, let's import the [FLUX.1-dev](https://huggingface.co/black-forest-labs/FLUX.1-dev) Space from the Hub and use it to generate an image. This tool requires network access.

```python
from smolagents import Tool # Ensure Tool is imported

image_generation_tool = Tool.from_space(
    "black-forest-labs/FLUX.1-schnell",
    name="image_generator",
    description="Generate an image from a prompt (requires network)."
)

# image = image_generation_tool("A sunny beach") # This call would use the network
# print(image) # This would likely be an AgentImage or path to the image
```
And voilà, here's your image! 🏖️

<img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/transformers/sunny_beach.webp">

Then you can use this tool just like any other tool.  For example, let's improve the prompt `a rabbit wearing a space suit` and generate an image of it. This example also shows how you can pass additional arguments to the agent.

```python
from smolagents import CodeAgent, InferenceClientModel, Tool # Ensure necessary imports

# model = InferenceClientModel(model_id="Qwen/Qwen2.5-Coder-32B-Instruct")
# agent = CodeAgent(tools=[image_generation_tool], model=model)

# agent.run(
#     "Improve this prompt, then generate an image of it.", additional_args={'user_prompt': 'A rabbit wearing a space suit'}
# )
```


### Manage your agent's toolbox

You can manage an agent's toolbox by adding or replacing a tool in attribute `agent.tools`, since it is a standard dictionary.

Let's add the `model_download_tool` to an existing agent initialized with only the default toolbox.

```python
from smolagents import CodeAgent, InferenceClientModel # Assuming CodeAgent and model_downloads_tool are defined

# model = InferenceClientModel(model_id="Qwen/Qwen2.5-Coder-32B-Instruct")
# model_downloads_tool = HFModelDownloadsTool() # Assuming it's defined as above

# agent = CodeAgent(tools=[], model=model, add_base_tools=True)
# agent.tools[model_downloads_tool.name] = model_downloads_tool
```
Now we can leverage the new tool:

```python
# agent.run(
#     "Can you give me the name of the model that has the most downloads in the 'text-to-video' task on the Hugging Face Hub but reverse the letters?"
# )
```


> [!TIP]
> Beware of not adding too many tools to an agent: this can overwhelm weaker LLM engines.


### Use a collection of tools

You can leverage tool collections by using [`ToolCollection`]. A `ToolCollection` is a way to group locally defined or loaded tools. It also supports loading tools from an MCP server. Note that `ToolCollection.from_hub()` has been removed.

#### Tool Collection from locally defined/loaded tools

You can create a `ToolCollection` by passing a list of your existing tool instances:
```python
from smolagents import ToolCollection, CodeAgent

# Assume model_downloads_tool and another_tool are already defined or loaded
# model_downloads_tool = HFModelDownloadsTool() 
# another_tool = MyOtherCustomTool() # Assuming MyOtherCustomTool is a valid Tool subclass

# tools_list = [model_downloads_tool, another_tool]
# local_tool_collection = ToolCollection(tools=tools_list)

# Then pass them as a list to initialize your agent
# model = ... # Initialize your model
# agent = CodeAgent(tools=[*local_tool_collection.tools], model=model, add_base_tools=True)
# agent.run("A task requiring one of these tools.")
```

#### Tool Collection from any MCP server (Network Dependent)

`ToolCollection` also supports loading tools from MCP (Model Context Protocol) servers. This functionality inherently requires network access to communicate with the MCP servers.
Leverage tools from the hundreds of MCP servers available on [glama.ai](https://glama.ai/mcp/servers) or [smithery.ai](https://smithery.ai/).

> [!WARNING]
> **Security Warning:** Using MCP servers comes with security risks:
> - **Trust is essential:** Only use MCP servers from trusted sources. Malicious servers can execute harmful code on your machine.
> - **Stdio-based MCP servers** will always execute code on your machine (that's their intended functionality).
> - **SSE-based MCP servers** while the remote MCP servers will not be able to execute code on your machine, still proceed with caution.
>
> Always verify the source and integrity of any MCP server before connecting to it, especially for production environments.

The MCP servers tools can be loaded with [`ToolCollection.from_mcp`].

For stdio-based MCP servers, pass the server parameters as an instance of `mcp.StdioServerParameters`:
```py
from smolagents import ToolCollection, CodeAgent # Assuming CodeAgent and a model are defined
from mcp import StdioServerParameters
import os # For os.environ

# server_parameters = StdioServerParameters(
#     command="uvx",
#     args=["--quiet", "pubmedmcp@0.1.3"],
#     env={"UV_PYTHON": "3.12", **os.environ},
# )

# model = ... # Initialize your model
# with ToolCollection.from_mcp(server_parameters, trust_remote_code=True) as tool_collection: # trust_remote_code is crucial here
#     agent = CodeAgent(tools=[*tool_collection.tools], model=model, add_base_tools=True)
#     agent.run("Please find a remedy for hangover.")
```

For SSE-based MCP servers, simply pass a dict with parameters to `mcp.client.sse.sse_client`:
```py
from smolagents import ToolCollection, CodeAgent # Assuming CodeAgent and a model are defined
import os # For os.environ

# model = ... # Initialize your model
# with ToolCollection.from_mcp({"url": "http://127.0.0.1:8000/sse"}, trust_remote_code=True) as tool_collection: # trust_remote_code is crucial
#     agent = CodeAgent(tools=[*tool_collection.tools], model=model, add_base_tools=True)
#     agent.run("Please find a remedy for hangover.")
```

> [!NOTE]
> The `trust_remote_code=True` parameter is essential when using MCP tools, as they involve executing code that may originate from an external server. Always ensure you trust the MCP server you are connecting to.
